# 寰宇 KTV｜作品集广告短片与首页交互

## 创意核心

**片名：把歌房带到任何聚会。** 约 60 秒，16:9 为主页主片，另裁一版 9:16。前半段让观众感到“聚会突然有了舞台”，中段用短暂、清晰的链路动画证明它不是单机播放器，结尾回到真实操作：多人点歌、房主控制、电视播放。

这支片应展示当前真实架构：**Pad 是房主控制台；播放电脑运行 KTV 和 mpv，并把 MV 输出到电视。** 房主和来宾通过房间网页操作。视频不把 Pad 描绘成直接解码或投放 MV 的设备，也不把公网隧道画成传输几 TB 视频的线路。

视觉语言沿用界面第一版：石墨黑、冰蓝、少量暖金。蓝色光线代表点歌与控制请求，暖金色代表 MV 从歌源到播放电脑再到电视。拓扑动画每次只亮当前使用的节点，避免一整张网络图压住聚会气氛。

## 60 秒分镜

| 时间 | 画面与动作 | 旁白 / 字幕 | 要证明的能力 |
| --- | --- | --- | --- |
| 00–05 | 客厅聚会已开始，音乐却只是背景声。有人笑着问“今晚谁点歌？”房主从沙发旁拿起 Pad。音效从环境噪声收束为一声轻脆的开机提示。 | **字幕：朋友到了。歌房呢？** | 真实使用场景 |
| 05–11 | Pad 打开寰宇 KTV 房主界面。特写：曲库与歌源里填着已挂载的 NAS 路径，歌曲索引数量出现；OpenList 网盘作为另一种可选歌源。画面切到桌边一台连接电视的笔记本。 | **旁白：歌，不必搬到聚会现场。** | 房主配置、多歌源 |
| 11–19 | 镜头从笔记本沿一道暖金光线穿过城市夜景，落到家中 NAS；另一条线从网盘图标接入 OpenList。两路汇入笔记本里的小型歌曲索引，视频文件图标仍留在各自歌源。 | **旁白：曲库留在自己的 NAS 或网盘；播放电脑只建立索引，按需读取。** | 远程 NAS、OpenList、索引与媒体分离 |
| 19–25 | 电视先显示 KTV 待机页上的房间二维码。笔记本的独立 mpv 窗口准备好在点歌后接管电视画面；Pad 仍显示房主设置。镜头明确带到“笔记本 → 电视”这条暖金链路。 | **字幕：一台播放电脑，负责舞台。** | 播放与控制分离 |
| 25–33 | 三位来宾各拿起手机扫电视二维码。一个手机的 Wi-Fi 图标关闭，显示 5G；他们输入来宾口令后进入同一房间。蓝色光线从手机经 HTTPS 房间入口到笔记本，不经过 NAS。 | **旁白：朋友扫一下，用 Wi-Fi，或用自己的流量，都能加入。** | 公网入口、多人会话、口令权限 |
| 33–43 | 手机搜歌并点歌，第一首进入队列；另一人按“下一首播放”。真实产品界面以清晰录屏叠在手机上。电视切到一段**原创或获授权**的 MV，歌声与欢呼声抬起。 | **旁白：每个人都能点歌，现场的顺序，大家一起决定。** | 搜索、排队、即刻插入下一首 |
| 43–51 | 房主在 Pad 上暂停一下让大家举杯，随后继续播放，切原伴唱、重唱；电视画面与 Pad 操作同步。快速回闪 NAS、HTTPS 房间、笔记本、电视四个节点，蓝/金两条线各走自己的路。 | **旁白：房主掌控节奏；音乐，从自己的歌源走向电视。** | 实时控制、媒体链路 |
| 51–60 | 回到全景：所有人面向电视合唱。最后定格于电视光线照亮的客厅，再收成产品名、GitHub 地址和两枚入口按钮。 | **主标题：把歌房带到任何聚会。** 副标题：**自己的曲库 · 多人点歌 · 远程也能唱** | 产品定位与作品集 CTA |

旁白只读上表句子；屏幕上的短字用于强调，不要让旁白重复操作按钮名称。音乐在 33 秒第一次点歌时进入主节奏，43 秒短暂抽掉鼓点以突出暂停动作，51 秒合唱达到情绪最高点。全片控制在约 55–65 秒。

## 首页交互：让观众看见部署能力

主片放在首页作品卡中的 **16:9 舞台窗口**，不要再让 MV 覆盖整个浏览器。窗口下方有一条四节点进度线：

1. **部署播放主机**：笔记本运行 KTV 与 mpv。
2. **连接自己的歌源**：NAS 或 OpenList 网盘建立索引。
3. **开放聚会房间**：HTTPS 入口、房主/来宾双口令、手机 5G 可加入。
4. **多人点歌与电视播放**：队列、下一首、房主控制。

视频播放到对应段落时高亮节点；用户也可以点任一节点，跳到该段 3–5 秒的短循环，并在旁边看到一句架构解释。最后放“看系统架构”和“查看 GitHub”两个按钮。手机端保留短片与可点的四张卡；弱网或系统要求减少动态效果时显示静态封面与文字，不自动播放声音。

这样首页先用聚会场景吸引人，再用**两条分开的线**把你的 production / deployment 能力讲明白：控制请求经公网入口进入房间；MV 由播放电脑从歌源读取并输出到电视。作品集不要把“部署”写成抽象标签，而要展示身份控制、媒体路由、曲库索引和跨网络可达这四个实际决定。

## 生成与剪辑建议

适合用 C-Dance 生成的是**真人氛围镜头**，不适合让模型直接生成可读的产品界面、二维码或真实网络图。建议分五段生成并统一演员、衣服、客厅、Pad 和电视的位置：00–05、05–11、19–25、25–33、51–60。每段 5–8 秒，留左右构图空间给后期文字。产品 UI 用真实录屏替换 Pad/手机屏幕；二维码由 KTV 实际房间生成；NAS、隧道和两条数据线用后期矢量动画完成。不要在生成画面里输入密码、token 或真实私人 NAS 地址。

可复用的真人镜头提示词：

> 现代城市公寓的晚间朋友聚会，五六位年轻成年人，自然轻松的真实情绪，桌上饮料和零食，房主拿起一台平板作为控制台，桌边有一台低调的笔记本连接大屏电视；电视屏幕保持纯暗色，便于后期替换。电影广告摄影，石墨黑环境、冷蓝屏幕边光、温暖肤色，35mm 镜头，真实手部动作和一致的人物服装，缓慢稳定运镜，16:9，无可读文字、无品牌商标、无假二维码、无生成的 UI。

再分别加动作约束：

- **开场**：聚会稍显安静，一人举起平板，大家转头看向电视。
- **设置**：房主在平板上轻点，镜头掠过笔记本和电视；屏幕留白给后期录屏。
- **扫码**：朋友举起手机对准电视角落，另一人的手机显示普通蜂窝网络状态；屏幕留白给后期 UI。
- **合唱**：真实开心的合唱反应和举杯，电视发出蓝色舞台光；避免模仿任何已知歌手或 MV。

11–19 秒的城市/NAS 镜头更适合 2D/3D motion graphics，而不是靠视频模型猜网络结构。选择一段原创或已获授权的音乐与 MV 占位画面；后期把点歌、排队和房主控制的**真实产品录屏**贴入设备屏幕。最终输出静音自动播放版本（首页）与有声完整版本（作品集详情页）。
